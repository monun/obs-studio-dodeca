## Purpose

OBS Studio Dodeca의 본체 업데이트 안내와 실행을 항상 비활성화하여 공식 OBS 배포로의 의도하지 않은 교체를 방지한다. 기존 설정과 12트랙 기능, 방송 서비스 및 게임 캡처에 필요한 보조 데이터 갱신을 보존하는 범위를 정의한다.

## ADDED Requirements

### Requirement: 본체 업데이트 조작 UI 제외

애플리케이션은 Windows·macOS·Linux에서 본체 업데이트 확인, 자동 업데이트 설정, 업데이트 채널 선택 및 본체 복구 조작을 사용자에게 표시하거나 조작 가능하게 제공해서는 안 된다(SHALL NOT). 운영체제의 애플리케이션 메뉴에 통합되는 항목에도 같은 제약을 적용해야 한다(SHALL).

#### Scenario: 도움말과 일반 설정 열기
- **WHEN** 사용자가 도움말 메뉴와 일반 설정 화면을 연다
- **THEN** 업데이트 확인과 복구 메뉴, 자동 업데이트 체크박스, 업데이트 채널 선택 및 비어 있는 업데이트 설정 그룹이 표시되지 않는다
- **AND** 관련 없는 메뉴와 설정은 계속 사용할 수 있다

#### Scenario: macOS 애플리케이션 메뉴 열기
- **WHEN** 사용자가 macOS의 애플리케이션 메뉴를 연다
- **THEN** 본체 업데이트 확인 항목을 표시하거나 실행할 수 없다

### Requirement: 본체 업데이트 작업 상시 비활성화

애플리케이션은 실행 중 본체 버전·업데이트 채널·매니페스트의 원격 조회, 본체 업데이트 파일 다운로드·검증·적용, 복구 실행 및 이를 위한 종료·재시작을 수행해서는 안 된다(SHALL NOT). 업데이트 가능 여부·오류·복구·설치 권유를 알리는 대화상자도 표시해서는 안 된다(SHALL NOT). 기존 설정·캐시, 자동 확인 시점, 메뉴나 설정에서 발생하던 요청으로 이 제약을 우회할 수 없어야 한다(SHALL).

#### Scenario: 업데이트가 활성화된 기존 설정으로 시작
- **WHEN** 자동 업데이트가 켜져 있고 마지막 확인 시점이 오래되었거나 설치 버전이 바뀐 기존 설정으로 앱을 시작한다
- **THEN** 본체 업데이트 서버 조회와 다운로드, 업데이트 대화상자 및 업데이트 실행기 기동이 발생하지 않는다

#### Scenario: 설정 저장과 이전 수동 요청 경로
- **WHEN** 사용자가 일반 설정을 저장하거나 이전 업데이트 확인·복구 요청을 전달하려고 시도한다
- **THEN** 본체 업데이트 작업을 시작하지 않는다
- **AND** 애플리케이션이 종료되거나 업데이트를 위해 재시작되지 않는다

#### Scenario: 기존 업데이트 캐시 존재
- **WHEN** 이전 실행에서 받은 업데이트 메타데이터와 실행 파일이 사용자 설정 디렉터리에 남아 있다
- **THEN** 해당 파일을 본체 업데이트나 복구에 사용하거나 실행하지 않는다
- **AND** 이 비활성화 변경을 이유로 기존 캐시 파일을 삭제하거나 수정하지 않는다

### Requirement: 새 소식 메뉴와 팝업 제외

애플리케이션은 ‘새 소식’(What's New) 메뉴와 자동·수동 팝업을 제공하거나 해당 안내를 위한 원격 메타데이터·웹 콘텐츠를 가져와서는 안 된다(SHALL NOT). 일반 브라우저 소스와 브라우저 도크의 동작은 유지해야 한다(SHALL).

#### Scenario: 새 버전 또는 새 설정으로 첫 실행
- **WHEN** 브라우저 기능이 포함된 빌드를 새 설정으로 시작하거나 새 소식을 아직 확인하지 않은 기존 설정으로 시작한다
- **THEN** 새 소식 팝업과 관련 네트워크 요청이 발생하지 않는다
- **AND** 새 소식 메뉴를 통해 팝업을 열 수도 없다

#### Scenario: 브라우저 소스 사용
- **WHEN** 사용자가 브라우저 소스나 브라우저 도크를 사용한다
- **THEN** 본체 업데이트와 새 소식의 비활성화 때문에 해당 기능이 차단되지 않는다

### Requirement: 업데이트가 제외된 빌드와 패키지

지원되는 프로젝트 빌드는 본체 업데이트 전용 실행 파일이나 업데이트 프레임워크를 생성·연결·배포 패키지에 포함하지 않아야 한다(SHALL). 기존 플랫폼 preset 또는 CMake 캐시에 업데이트·새 소식을 활성화하는 값이 남아 있어도 본체 업데이트 기능이 되살아나서는 안 된다(SHALL NOT).

#### Scenario: Windows 빌드와 새 설치 위치
- **WHEN** Windows preset으로 빌드하여 비어 있는 설치 위치에 설치하거나 portable 패키지를 만든다
- **THEN** 본체 업데이트 실행기 빌드 대상과 실행 파일이 생성·포함되지 않는다
- **AND** 애플리케이션은 정상적으로 시작한다

#### Scenario: 기존 macOS 업데이트 설정 사용
- **WHEN** 업데이트 피드·키가 지정된 기존 macOS preset 또는 캐시를 사용해 새 앱 번들을 만든다
- **THEN** 본체 업데이트 프레임워크와 활성 업데이트 피드 설정이 번들에 포함되지 않는다
- **AND** 애플리케이션 메뉴나 백그라운드 작업에서 본체 업데이트를 시작하지 않는다

#### Scenario: 새 소식 활성화 옵션이 남은 빌드
- **WHEN** 새 소식 활성화 값이 남아 있고 브라우저 기능도 켜진 구성으로 지원 플랫폼을 빌드한다
- **THEN** 새 소식 기능은 계속 제외되고 나머지 프런트엔드는 빌드된다

### Requirement: 기존 설정과 실행 방법의 호환성

애플리케이션은 기존 장면 모음·프로필과 저장된 업데이트 설정을 강제 삭제하거나 재작성하지 않고 불러올 수 있어야 한다(SHALL). 저장된 업데이트 설정은 본체 업데이트를 활성화할 수 없어야 하며(SHALL NOT), 기존 `--disable-updater` 실행 인자는 계속 허용해야 한다(SHALL). 해당 인자나 기존 비활성화 표식 파일의 유무에 관계없이 본체 업데이트는 제외되어야 한다(SHALL).

#### Scenario: 기존 설정 저장 후 다시 시작
- **WHEN** 사용자가 기존 설정을 불러와 관련 없는 일반 설정을 저장하고 다시 시작한다
- **THEN** 기존 업데이트 설정 값은 이 변경 때문에 삭제·초기화되지 않으며 본체 업데이트도 실행되지 않는다
- **AND** 장면 모음·프로필과 1~12번 오디오 트랙 설정을 보존한다

#### Scenario: 기존 바로가기와 portable 실행
- **WHEN** `--disable-updater` 인자를 사용하거나 생략하고, 비활성화 표식 파일이 있거나 없는 환경에서 일반 모드 또는 portable 모드로 시작한다
- **THEN** 업데이트 옵션 때문에 실행 오류가 발생하지 않는다
- **AND** 모든 경우에서 본체 업데이트 UI와 작업이 비활성 상태다

### Requirement: 보조 데이터 갱신과 일반 기능 보존

본체 업데이트 비활성화는 방송 서비스 목록·서버 정보 및 게임 캡처 호환성 데이터의 기존 갱신 정책을 변경해서는 안 된다(SHALL NOT). 인증, 방송, 12트랙 녹화·리플레이·리먹스, 사용자가 여는 릴리스 노트 웹 링크에도 이 변경으로 인한 제한을 추가해서는 안 된다(SHALL NOT).

#### Scenario: 방송 서비스 데이터 갱신
- **WHEN** 기존 설정과 빌드 옵션이 방송 서비스 목록 또는 서버 정보의 갱신을 허용한다
- **THEN** 해당 데이터는 기존 경로로 조회·갱신되고 방송 설정에서 사용할 수 있다
- **AND** 이 동작으로 본체 업데이트를 실행하지 않는다

#### Scenario: 게임 캡처 호환성 데이터 갱신
- **WHEN** Windows 빌드가 게임 캡처 호환성 데이터 갱신을 허용한다
- **THEN** 기존 호환성 데이터 갱신과 게임 캡처 초기화가 유지된다

#### Scenario: 기존 녹화와 정보 열람
- **WHEN** 사용자가 1~12번 트랙 설정으로 녹화하거나 릴리스 노트 메뉴를 연다
- **THEN** 기존 오디오 설정과 출력 동작을 유지하고 릴리스 노트 웹 페이지를 열 수 있다
- **AND** OBS 내부의 업데이트 안내나 업데이트 실행이 시작되지 않는다
